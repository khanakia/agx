# Shell integration

A program cannot change its parent shell's directory or environment. `agx shell-init` prints a small block of shell code that can: it defines an `agx` function so `agx new`, `agx resume` and `agx ws` leave your shell inside the session folder, tells your terminal where you are (OSC 7) so new tabs open there, adds one function per `shell.aliases` entry, and adds `aglogin` for a per-terminal login. Everything works without it; your shell just stays where it was. This page also covers tab completion.

## Before you start

- zsh or bash. Those are the two shells `agx shell-init` supports; bash uses the same script.
- `agx` on your `PATH` (the generated code calls `command agx`).
- Optional: aliases in `~/.agx/config.yaml` under `shell.aliases`; see [Config reference](config-reference.md#shell).

## Step 1 — Load the layer

Add one line to `~/.zshrc`:

```sh
eval "$(agx shell-init zsh)"
```

or to `~/.bashrc`:

```sh
eval "$(agx shell-init bash)"
```

With no argument, `agx shell-init` prints the zsh script. The code is regenerated on every shell start, so it always matches the installed binary and the current config; edit the config, never the output. Open a new shell, then confirm:

```sh
agx doctor | grep shell
```

## Step 2 — Understand the launch-plan protocol

For `new`, `resume` and `ws`, the function does this (`internal/shellinit/shellinit.go`):

1. Creates a private temp file and runs the binary with `AGX_PLAN_FILE` pointing at it.
2. The binary does all the work (creates the folder, picks the conversation) and, instead of launching, writes a small JSON plan with mode 0600: the folder, the profile, the conversation id, extra arguments and the `--login` value. Never a token or a secret.
3. If the binary failed or wrote nothing (for example `--dry-run`), the function removes the file and returns the binary's exit code.
4. Otherwise it asks the binary for the folder (`agx exec --plan FILE --print-dir`), `cd`s there, emits OSC 7, and runs `agx exec --plan FILE`. `exec` deletes the plan before it starts the agent, so a plan is used once.

Every other subcommand goes straight to `command agx "$@"`. `agx exec` is hidden from `--help` because only the shell layer uses it.

## Step 3 — Add aliases

```yaml
# ~/.agx/config.yaml
shell:
  aliases:
    cl: run -p personal
    clw: run -p work
    cla: run -p auto
    clnew: new -p personal
    clr: resume
```

Each entry becomes a function that calls the `agx` function, so `clnew` lands in the new folder and every extra argument passes through (`clw --login personal`, `clr --last`). Names match `^[A-Za-z_][A-Za-z0-9_-]*$`; values use only letters, digits, spaces and `_./:=@+-`, because they are pasted into shell code as they are (`config/config.go`, `aliasArgsPattern`). The functions are emitted sorted by name.

## Step 4 — Switch logins per terminal with `aglogin`

```sh
aglogin personal
```

`aglogin NAME` runs the hidden `agx login exists NAME` (exit 0 for a login or `home`, an error listing the known names otherwise), then exports `AGX_LOGIN=NAME`, so every launch in this terminal spends that login's quota until you run `aglogin` with no argument. See [Choosing a login](../logins/choosing-a-login.md).

## Step 5 — Tab completion

`agx completion` prints a completion script for bash, zsh, fish or powershell. Load it after the shell layer, in the same rc file:

```sh
# ~/.zshrc (completion must be enabled: autoload -U compinit; compinit)
eval "$(agx shell-init zsh)"
source <(agx completion zsh)
```

```sh
# ~/.bashrc (needs the bash-completion package)
eval "$(agx shell-init bash)"
source <(agx completion bash)
```

```sh
# ~/.config/fish/config.fish (completion only; fish has no shell layer)
agx completion fish | source
```

`agx completion zsh --help` (and the same for each shell) prints the install variants for that shell.

## Try it

The script generated for a config with three aliases:

```text
$ agx shell-init zsh
# agx shell integration (zsh) — generated by `agx shell-init zsh`.
# Regenerated on every shell start; edit the config, not this output.
export AGX_SHELL_INIT=zsh

# Report the cwd to the terminal (OSC 7) so new tabs / splits inherit it.
_agx_emit_cwd() {
  printf '\033]7;file://%s%s\033\\' "${HOST:-$(hostname)}" "$PWD"
}

# agx: for new / resume / ws the binary writes a launch plan instead of
# launching; this function then cd's into the plan's directory (which a child
# process cannot do for its parent shell) and hands the plan back to exec.
agx() {
  case "$1" in
    new|resume|ws)
      local plan dir rc
      plan=$(mktemp "${TMPDIR:-/tmp}/agx-plan.XXXXXX") || return 1
      AGX_PLAN_FILE="$plan" command agx "$@"
      rc=$?
      if [ "$rc" -ne 0 ] || [ ! -s "$plan" ]; then
        command rm -f -- "$plan"
        return "$rc"
      fi
      dir=$(command agx exec --plan "$plan" --print-dir) || { command rm -f -- "$plan"; return 1; }
      cd -- "$dir" || { command rm -f -- "$plan"; return 1; }
      _agx_emit_cwd
      command agx exec --plan "$plan"
      ;;
    *)
      command agx "$@"
      ;;
  esac
}

# aglogin NAME: every run in this terminal spends login NAME's quota
# (exports AGX_LOGIN); aglogin with no argument undoes it. A function,
# because a child process cannot change its parent shell's environment.
aglogin() {
  if [ "$#" -eq 0 ]; then
    unset AGX_LOGIN
    echo "agx: AGX_LOGIN unset — profile and provider defaults apply" >&2
    return 0
  fi
  command agx login exists "$1" || return 1
  export AGX_LOGIN="$1"
  echo "agx: AGX_LOGIN=$1 in this terminal (aglogin with no argument undoes it)" >&2
}

cl() { agx run -p personal "$@"; }
clnew() { agx new -p personal "$@"; }
clw() { agx run -p work "$@"; }
```

The plan protocol by hand, in a throwaway home (`/home/you`):

```text
$ AGX_PLAN_FILE=/home/you/plan.json agx new -p work demo
$ cat /home/you/plan.json
{"version":1,"dir":"/home/you/agx-sessions/demo_20261017_024831","profile":"work"}
$ ls -l /home/you/plan.json
-rw------- 1 you you 94 Oct 17 02:48 /home/you/plan.json
$ agx exec --plan /home/you/plan.json --print-dir
/home/you/agx-sessions/demo_20261017_024831
```

## Pitfalls

- **fish has no shell layer.** `agx shell-init fish` fails with `agx: shellinit: unsupported shell "fish" (supported: [zsh bash])` (exit 2). Completion for fish works.
- **`command agx` bypasses the layer.** So do scripts, which do not load your rc file: `agx new` there launches in the new folder but your shell stays where it was. That is expected, not a failure.
- **Upgrading agx can leave an old layer in open shells.** A plan carries a version, and `agx exec` refuses another one: `agx: plan version 0, want 1 — re-run `eval "$(agx shell-init zsh)"`` (`internal/cli/launch.go`, `planVersion`). Open a new shell or re-run the `eval` line.
- **Alias changes need a new shell.** The functions are generated when the rc file runs; after editing `shell.aliases`, open a new shell or re-run the `eval` line.
- **An alias with shell syntax is refused, not escaped.** `bad: "run -p personal; rm -rf ~"` stops every agx command with `shell.aliases.bad: only letters, digits, spaces and _./:=@+- are allowed`, including `agx shell-init` itself, so a broken config means no aliases until it is fixed.
- **OSC 7 is sent only after `new`, `resume` and `ws` change folder.** The function does not hook every `cd`; a terminal that tracks the folder through OSC 7 learns about other moves from your own prompt setup, if any.
- **`aglogin` refuses `auto`.** `aglogin auto` prints the `"auto" is accepted only as --login …` error and returns 1, leaving `AGX_LOGIN` as it was.
